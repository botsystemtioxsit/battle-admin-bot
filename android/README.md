# БАТТЛ Админ — Android

Минимальное Android-приложение: одно `WebView`, открывающее ту же живую
панель (`public/admin.html`), что и браузерная версия и десктоп-приложение
в `../desktop/`. Никакой отдельной копии панели внутри — значит, любое
обновление панели долетает сюда само, без пересборки APK.

Вход внутри работает как обычно (email-заявка или Telegram, см.
`src/admin.html`) — ничего специального для Android-версии настраивать не
нужно.

## Сборка

Собирается через GitHub Actions (Android SDK + Gradle не нужны локально):
вкладка **Actions** → **Build Android APK** → **Run workflow**. Готовый
`battle-admin.apk` публикуется как файл к GitHub Release этого репозитория.

Это debug-сборка (не для Google Play), подписанная постоянным ключом — см.
«Подпись APK» ниже. Этого достаточно, чтобы установить APK на телефон
напрямую. При установке Android спросит разрешить «Установка из неизвестных
источников» — это нормально для APK не из Google Play.

Релиз всегда публикуется под одним и тем же фиксированным тегом
`android-latest` — прямая ссылка на APK не меняется между сборками:
`https://github.com/botsystemtioxsit/battle-admin-bot/releases/download/android-latest/battle-admin.apk`

## Проверка обновлений

Начиная с версии 1.1.0 приложение само проверяет обновления при каждом
запуске: тихо сверяет свой `versionCode` с `version.json`, который
публикуется рядом с APK в том же релизе `android-latest` (см.
`MainActivity.checkForUpdate` и последний шаг
`.github/workflows/build-android-apk.yml`). Если на GitHub лежит версия
новее — показывает диалог «Доступно обновление», по кнопке «Обновить»
открывает прямую ссылку на APK в браузере. Ничего не показывает и не
ломается при отсутствии сети — это фоновая проверка, а не блокирующий
экран.

Установку человек, как и в самый первый раз, довершает сам — тапом по
скачанному файлу.

Была опробована и полная автоматизация — скачивание через `DownloadManager`
и сразу системный установщик поверх скачанного файла (для этого требовалось
разрешение `REQUEST_INSTALL_PACKAGES`), в точности как самообновление
Telegram. Но именно эта связка — сторонний APK не из Google Play, который
сам умеет ставить другие APK — это ровно то поведение, которое Google Play
Защита распознаёт как троян-дроппер, и заблокировала сам APK при установке
(«Вредоносное приложение заблокировано»). Причина не в качестве кода:
у Telegram эта же механика работает без блокировки только потому, что их
сертификат Google уже видел на миллионах установок — у отладочно
подписанного APK без истории такой репутации нет и не может появиться
без прохождения через инфраструктуру Google Play (Play Console, Internal
App Sharing и т.п.), а это требует платной регистрации разработчика —
принципиально не годится для этого проекта (см. Firebase-ограничение
"только бесплатный план" в других CLAUDE.md этого проекта — тот же
принцип применён и здесь). Поэтому автоматическую установку убрали
совсем: приложение сообщает об обновлении и указывает, где его взять, но
саму установку больше не трогает. `REQUEST_INSTALL_PACKAGES` приложение не
запрашивает.

Это работает только начиная со следующей сборки после текущей — версия,
уже стоящая на телефоне без этого кода, сама узнать о существовании
проверки обновлений не может; её придётся поставить вручную один
последний раз.

## Подпись APK

Google Play Защита блокирует установку со словами «никогда не проверяла
приложение этого разработчика», если APK подписан ключом, которого она
ещё не видела. Раньше CI при каждой сборке создавал **новый случайный
отладочный ключ** — поэтому каждая версия выглядела как приложение от
нового разработчика, а поверх предыдущей версии она вообще не
устанавливалась (подпись не совпадает — Android просит сначала удалить
старое приложение, а с ним и его данные).

Теперь APK подписывается **постоянным ключом**. Это один и тот же ключ в
обоих репозиториях — `index.html` (игра) и `battle-admin-bot` (панель),
поэтому для Google это один и тот же разработчик. Сам файл ключа лежит в
секретах GitHub (**Settings → Secrets and variables → Actions → New
repository secret**), в имени `ANDROID_KEYSTORE_BASE64`. Пароль (`battle-android`) и
алиас (`battle`) не секретны — они вшиты в workflow: секретен сам файл.

- Секрета нет — сборка идёт как раньше, одноразовым отладочным ключом, в
  логе жёлтое предупреждение. Ничего не ломается, но предупреждение Play
  Защиты и невозможность обновиться поверх остаются.
- Секрет есть — в логе шага **Show signing certificate** виден отпечаток
  сертификата, он должен быть **одним и тем же** от сборки к сборке.
- **Ключ нельзя терять и нельзя менять:** с новым ключом Android снова
  откажется ставить APK поверх старого. Копию текста секрета стоит хранить
  в надёжном месте (например, «Избранное» в Telegram).
- Ключ не должен попадать в репозиторий: репозиторий публичный, а значит любой мог бы
  подписать «обновление» с вашим именем пакета.

При первом переходе со старого (отладочного) ключа на постоянный Android не
поставит новую сборку поверх установленной — старое приложение надо один раз
удалить. Дальше обновления ставятся поверх. Предупреждение Play Защиты при
самой первой установке всё равно может появиться (ссылка «Все равно
установить» внизу диалога) — после неё Google уже знает этот сертификат.

## Значок приложения

Шестерёнка со звездой на чёрном фоне. Исходник — квадрат 2000×2000.

- **Android 8+ — адаптивный значок** (`app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml` и `ic_launcher_round.xml`): слои `ic_launcher_background`, `ic_launcher_foreground` и `ic_launcher_monochrome` во всех плотностях (108/162/216/324/432 px). Система сама режет его по форме темы телефона, а слой `monochrome` нужен для «тематических значков» (Android 13+): без него launcher красит значок в цвета обоев как попало и вместо картинки получается тусклая плитка. Лишнее из картинки в слой не должно выходить за центральные 72 из 108 dp (иначе круглая маска обрежет края).
- **Android 7 и все старые версии** — обычные PNG `ic_launcher.png` (скруглённый квадрат) и `ic_launcher_round.png` (круг) в `mipmap-*dpi` (48/72/96/144/192 px).
- Десктоп (`../desktop/icon.png`, 512×512) — отдельный файл.

Если на телефоне после переустановки значок остался старым — проверьте версию приложения (Настройки → Приложения) и кэш рабочего стола; сам файл APK иконки внутри содержит правильные.

## Проверочная версия значка

Тип сборки `iconTest` (`./gradlew assembleIconTest`) — то же приложение с другим именем пакета (`.icontest`) и названием «… (тест значка)». Ставится **рядом** с обычным как отдельное приложение: так видно, показывает ли телефон новый значок, без влияния старой установки, ярлыков и кэша лаунчера. CI собирает её только из веток (не из `main`) и кладёт в тестовый релиз `android-test` как `battle-admin-icontest.apk`; этот релиз удаляется при выкладке в `main`.
