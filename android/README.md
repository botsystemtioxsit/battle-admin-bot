# БАТТЛ Админ — Android

Минимальное Android-приложение: одно `WebView`, открывающее ту же живую
панель (`public/admin.html`), что и браузерная версия и десктоп-приложение
в `../desktop/`. Никакой отдельной копии панели внутри — значит, любое
обновление панели долетает сюда само, без пересборки APK.

Вход внутри работает как обычно (email-заявка или Telegram, см.
`src/admin.html`) — ничего специального для Android-версии настраивать не
нужно.

## Сборка

Собирается через GitHub Actions (Android SDK + Gradle не нужны локально):
вкладка **Actions** → **Build Android APK** → **Run workflow**. Готовый
`app-debug.apk` публикуется как файл к GitHub Release этого репозитория.

Это debug-сборка (подписана отладочным ключом Android, а не для
Google Play) — этого достаточно, чтобы установить APK на телефон напрямую.
При установке Android спросит разрешить «Установка из неизвестных
источников» — это нормально для APK не из Google Play.

Релиз всегда публикуется под одним и тем же фиксированным тегом
`android-latest` — прямая ссылка на APK не меняется между сборками:
`https://github.com/botsystemtioxsit/battle-admin-bot/releases/download/android-latest/app-debug.apk`

## Проверка обновлений

Начиная с версии 1.1.0 приложение само проверяет обновления при каждом
запуске: тихо сверяет свой `versionCode` с `version.json`, который
публикуется рядом с APK в том же релизе `android-latest` (см.
`MainActivity.checkForUpdate` и последний шаг
`.github/workflows/build-android-apk.yml`). Если на GitHub лежит версия
новее — показывает диалог «Доступно обновление», по кнопке «Обновить»
открывает прямую ссылку на APK в браузере. Ничего не показывает и не
ломается при отсутствии сети — это фоновая проверка, а не блокирующий
экран.

Установку человек, как и в самый первый раз, довершает сам — тапом по
скачанному файлу.

Была опробована и полная автоматизация — скачивание через `DownloadManager`
и сразу системный установщик поверх скачанного файла (для этого требовалось
разрешение `REQUEST_INSTALL_PACKAGES`), в точности как самообновление
Telegram. Но именно эта связка — сторонний APK не из Google Play, который
сам умеет ставить другие APK — это ровно то поведение, которое Google Play
Защита распознаёт как троян-дроппер, и заблокировала сам APK при установке
(«Вредоносное приложение заблокировано»). Причина не в качестве кода:
у Telegram эта же механика работает без блокировки только потому, что их
сертификат Google уже видел на миллионах установок — у отладочно
подписанного APK без истории такой репутации нет и не может появиться
без прохождения через инфраструктуру Google Play (Play Console, Internal
App Sharing и т.п.), а это требует платной регистрации разработчика —
принципиально не годится для этого проекта (см. Firebase-ограничение
"только бесплатный план" в других CLAUDE.md этого проекта — тот же
принцип применён и здесь). Поэтому автоматическую установку убрали
совсем: приложение сообщает об обновлении и указывает, где его взять, но
саму установку больше не трогает. `REQUEST_INSTALL_PACKAGES` приложение не
запрашивает.

Это работает только начиная со следующей сборки после текущей — версия,
уже стоящая на телефоне без этого кода, сама узнать о существовании
проверки обновлений не может; её придётся поставить вручную один
последний раз.

## Свой значок приложения

Сейчас используется тот же `desktop/icon.png` (чёрно-белый пиксельный
череп), скопированный во все `app/src/main/res/mipmap-*/ic_launcher*.png`.
Чтобы заменить — положите свой квадратный PNG под тем же именем в каждую
из папок `mipmap-mdpi/hdpi/xhdpi/xxhdpi/xxxhdpi`.
